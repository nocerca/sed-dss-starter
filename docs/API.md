# REST API v1 и совместимость

Точный контракт: [openapi.json](openapi.json), интерактивный интерфейс запущенного сервиса — `/docs`. Все `/api/v1/*` требуют `X-API-Key`. Ошибка авторизации — 401. Каждый ответ получает сгенерированный сервером `X-Request-ID`; входное значение не используется.

В Swagger операции сгруппированы по назначению, у каждого параметра есть русское описание. Для ответа откройте **Schema**: раскрываются `AnalysisResponse`, элементы `findings` и вложенные поля `metrics`. В **Example Value** доступны синтетические варианты `rules_only`, `hybrid` и `partial`. Описание авторизации в **Authorize** поясняет различие APP_API_KEY и ключей модели. Swagger также показывает длительность выполненного запроса.

## Анализ

`POST /api/v1/analyze`, `multipart/form-data`:

| Поле | Значение |
|---|---|
| `file` | Обязательный DOCX, по умолчанию до 5 МиБ; содержимое ZIP дополнительно проверяется |
| `use_llm` | По умолчанию `false` |
| `allow_external_transfer` | По умолчанию `false`; явное согласие для этого запроса |
| `use_language_checks` | По умолчанию `false`; отдельный локальный LanguageTool, без внешней модели; нужен профиль `language` и включение адаптера |
| `use_cache` | По умолчанию `true`; повторно выдать успешный тяжёлый отчёт при полном совпадении входов. `false` обходит кэш для запроса; для нового вычисления также нужен новый Idempotency-Key либо отсутствие ключа |
| `external_document_id` | Необязательный идентификатор СЭД, 1–128 символов |
| `document_type` | `unspecified` по умолчанию; `request`, `response`, `notification`, `cover_letter` |
| `template_id` | Необязательный идентификатор шаблона, 1–64 символа: буквы ASCII, цифры, `_`, `.`, `-` |
| `policy_profile` | Необязательное `office_instruction_letters`: явное применение реализованной части предоставленной инструкции. Без поля остаются прежние эвристики |

`external_document_id` и имя файла сохраняются для связи с СЭД, но не включаются в модельный запрос. Текст письма сам может содержать идентификаторы: отдельного автоматического обезличивания нет. Тип и шаблон фильтруют применимость правил; указание шаблона не означает проверку его визуального оформления.

Ответ содержит `id`, `filename`, `mode`, `provider`, `status`, `findings`, `metrics`, `warnings`, `created_at`, а также метаданные, `request_id` и `ruleset_version`. `request_id` в отчёте относится к первоначальному анализу, заголовок HTTP — к текущему запросу.

- `rules_only / completed`: правила выполнены без модели.
- `hybrid / completed`: правила и модельная обработка завершились; это не гарантия качества замечаний.
- `rules_fallback / partial`: правила сохранены, модельная часть завершилась ошибкой.
- `processing`: предварительные результаты сохранены; исход модельного вызова ещё не определён.

Замечание содержит категорию, критичность, цитату/доказательство, объяснение и рекомендацию; `fragment_id` и `rule_version` необязательны. `verified=true` у эвристики подтверждает её детерминированное условие. Выводы модели имеют `verified=false`. `quality_score=null`: общего балла нет.

## Повторные запросы

Необязательный заголовок `Idempotency-Key`: 8–128 символов ASCII из букв, цифр, `_`, `.`, `:`, `-`. Без ключа каждый POST создаёт новый отчёт.

| Ситуация с тем же ключом | Результат |
|---|---|
| Те же байты файла, имя и параметры; отчёт готов | 200, тот же отчёт, `Idempotency-Replayed: true`; нового модельного вызова нет |
| Изменён файл или любой учитываемый параметр | 409 |
| Первый запрос ещё обрабатывается | 409, `Retry-After: 2` |
| Отчёт удалён | 410; повторная обработка не запускается |

Ключ и отпечаток запроса хранятся как HMAC с отдельным `IDEMPOTENCY_SECRET`. Секрет должен оставаться стабильным между перезапусками. Изменение секрета лишает старые ключи возможности находить прежние записи; это не обычный способ повторить запрос.

Результаты правил и маркер обработки фиксируются перед модельным вызовом. После аварийной остановки отчёт может остаться `processing`: сервис не пересылает письмо автоматически при неизвестном исходе предыдущей передачи. Проверьте отчёт/обстоятельства; новый ключ запускает новый анализ намеренно. При повторе модельного запроса согласие и глобальное разрешение проверяются заново до возврата отчёта.

## Остальные операции

| Метод и путь | Назначение |
|---|---|
| `GET /api/v1/capabilities` | Форматы, лимиты, включён ли внешний анализ; модель и её доступность не проверяются |
| `GET /api/v1/reports` | Список; `limit=1..100` (20 по умолчанию), `offset`, необязательный UUID `request_id` |
| `GET /api/v1/reports/{id}` | Сохранённый отчёт, 404 при отсутствии |
| `DELETE /api/v1/reports/{id}` | 204; удаляет отчёт, сохраняет маркер использованного ключа |
| `GET /api/v1/rules` | Текущие спецификации, версии, источники, применимость и состояние `enabled` |
| `GET /api/v1/rules/{code}/versions` | Сохранённые версии конкретного правила |
| `POST /api/v1/knowledge/documents` | DOCX/TXT, `kind=good|bad|normative`, необязательный `source_ref` |
| `GET /api/v1/knowledge/documents` | Метаданные загруженных документов базы знаний |
| `DELETE /api/v1/knowledge/documents/{id}` | Удаление документа базы знаний |

Загрузка `kind=normative` сама по себе не доказывает нормативный статус или применимость текста. Retrieval — поиск по словам. Corpus API готов, но 20–40 реальных документов не загружались и качество поиска не измерялось.

`GET /health/live` — живость процесса. `GET /health/ready` — доступность БД, 503 при её недоступности. Оба открыты и не проверяют модель/OpenClaw: правила должны работать независимо от них.

Ошибки анализа: 409 — нет необходимых разрешений на модель; 413 — превышен лимит; 415 — неподдерживаемое расширение; 422 — неверные поля/повреждённый DOCX/пустой файл. Ошибка провайдера после принятия запроса отражается как HTTP 200 с `status=partial` и объяснением в `warnings`.

## Расширения v0.6

Добавлен кэш успешных отчётов для запросов с моделью/LanguageTool, поле use_cache и заголовок Analysis-Cache=hit/miss/bypass. Параллельный дубль другого ключа в одном процессе возвращает 409, Analysis-Cache=busy, Retry-After=2. Быстрые проверки только правилами не кэшируются. При hit возвращается прежний отчёт с прежними id/created_at/request_id/таймингами; X-Request-ID и Server-Timing относятся к текущему HTTP-запросу. HTTP Cache-Control=no-store запрещает сохранение приватного ответа браузером/прокси.

Отсутствие use_cache/true сохраняет старые отпечатки идемпотентности; false учитывается отдельно. Идемпотентность имеет приоритет над кэшем и не ограничена его TTL. Новые ключи могут ссылаться на один отчёт; удаление отчёта делает все эти ключи недействующими с 410. После удаления новый запрос без прежнего ключа выполняет новый анализ. Авторизация и модельное согласие проверяются до любого повторного использования.

Настройки и область кэша — capabilities.analysis_cache. В памяти хранятся только HMAC-ключи/ID/срок действия, дополнительных таблиц и миграций нет. Полная схема инвалидации, ограничения одного процесса и использование в Postman — [CACHE.md](CACHE.md).

## Расширения v0.5

В v0.5.1 сообщения локальных замечаний формируются по наблюдаемым значениям: место, конкретное отклонение и действие. Results в metrics.policy_checks дополнены message/recommendation. Для сравнений с основным текстом expected содержит фактическую эталонную гарнитуру/кегль, если они установлены. В warnings указаны конкретные причины пропуска и действия; предупреждения об изображениях/полях Word условные. Формат warnings остаётся массивом строк. Клиент должен ориентироваться на code/outcome, а не разбирать русскую формулировку. Новых обязательных полей нет, условия правил и версии реестра сохранены. Повтор со старым ключом вернёт старый сохранённый отчёт.

Добавлено необязательное поле `policy_profile=office_instruction_letters`. Профиль входит в идемпотентность; отсутствие поля сохраняет прежние отпечатки запросов, смена профиля с прежним ключом даёт 409. Поле не передаётся модели. Пути остаются `/api/v1`.

В `metrics.policy_checks` находятся результаты реализованных проверок: `code`, `outcome` (pass/violation/insufficient_data), `fragment_id`, `expected`, `observed`, `reason`, `source_ref`. `roles` показывает основания выделения блоков; `counts` считает исходы, `truncated` отражает усечение. Результаты ограничены 2000 записями и 200 замечаниями; при усечении отчёт partial. Без профиля status=not_requested. Недостаток данных не превращается в нарушение. Completed означает завершение доступных проверок, не соответствие всей инструкции.

У замечания добавлены необязательные `expected`, `observed`, `applicability_reason`. Для прежних эвристик и модели они null. В реестре появился источник `instruction`, означающий предоставленную организационную инструкцию без экспертного подтверждения (`verified=false`), и условие `applicability.policy_profiles`. Клиенты с жёстким перечислением типов источника должны учесть новое значение. `method` остаётся rule/llm/language_tool.

Реестр — `letters-0.5.0`: пять прежних эвристик получили версии 1.0.1 из-за исправления повреждённых русских описаний и расширения спецификации; условия их срабатывания сохранены. Добавлены 16 проверок/диагностик профиля версии 1.0.0. Прежние неизменяемые спецификации и отчёты сохраняются. Изменения хранятся в существующих JSON-полях; новой миграции схемы нет.

## Расширения v0.4

Новых обязательных полей нет, пути остаются `/api/v1`. Добавлены необязательный `use_language_checks`, признак `local_language_checks_available` в capabilities и дополнительные объекты в `metrics`:

| Объект | Назначение |
|---|---|
| `document_profile` | Эвристическая классификация likely_letter/likely_non_letter/undetermined, версия и коды признаков |
| `structure` | Счётчики заголовков Word, OOXML-ссылок на изображения и таблиц |
| `language_check` | Запрос/исход локального языка, версия, объём проверки, усечение и число замечаний |
| `llm_validation` | Предложено моделью, принято фильтром, добавлено в отчёт, повторы и причины отклонения |
| `timings_ms` | Реальные замеры parse/profile/rules/language/retrieval/llm_gateway/initial_save; пропущенные этапы — null |

`total_before_final_save_ms` измеряется до последней записи БД, без сериализации и сетевой передачи. `llm_gateway_ms` объединяет шлюз и внешний backend: раздельных замеров внутри них нет. `Server-Timing` описывает текущий HTTP-запрос; при идемпотентном повторе метрики самого отчёта остаются прежними. Старые отчёты не получают придуманные замеры задним числом.

Новый `method=language_tool` требует обновления клиентов с жёстким перечислением методов. Его критичность — info, verified=false, версия — 6.6. В режиме `rules_only` может выполняться локальный язык; `partial` теперь означает сбой любой запрошенной дополнительной проверки. Например, `hybrid / partial` возможен, если LLM завершилась, а локальный LanguageTool — нет. Подробности — `warnings` и `metrics.language_check`.

Флаг языка входит в идемпотентность; отсутствие/false сохраняет отпечатки прежних запросов. Смена на true с прежним ключом даёт 409. Согласие на внешнюю модель не требуется для локального LanguageTool и по-прежнему обязательно для LLM. Публичные адреса языкового API запрещены независимо от внешнего согласия.

Модельные замечания фильтруются консервативно и могут измениться относительно v0.3. Причины и ограничения формально описаны в [RULES.md](RULES.md); научная точность не заявляется.

## Изменения v0.3

Дополнение T08: расширены только описания Swagger/OpenAPI и примеры. Обязательные поля, значения по умолчанию, пути, проверки согласия и формат реальных ответов сохранены. Метрики дополнены вложенными описаниями в JSON Schema без изменения их runtime-валидации; это сохраняет совместимость с прежними отчётами.

Пути остаются под `/api/v1`. Добавлены необязательные поля анализа/ответа, правила с версиями, список/удаление отчётов и идемпотентность. Прежний минимальный POST с одним DOCX продолжает работать. Клиент должен допускать новые поля JSON и обрабатывать `partial`, а не считать любой 200 полной проверкой.

`GET /api/v1/rules` теперь возвращает типизированные спецификации вместо сокращённых карточек; клиентам этого endpoint нужно обновить разбор. Локальный `config/rules.json` изменён с массива на объект с `version` и `rules`; это изменение формата конфигурации, не загрузочного REST API. Изменение спецификации требует новой версии; подмена содержимого существующей версии останавливает запуск.

Генерация снимка: `python scripts/export_openapi.py`; проверка актуальности: та же команда с `--check`. Контракт и совместимость покрыты тестами.

## Веб-клиент v0.7 и совместимость

Корневая страница `/` и `/assets/*` обслуживают браузерный клиент; в OpenAPI они не включены. Это добавление не меняет `/api/v1`, схему отчёта, требования к авторизации, multipart-параметры или идемпотентность. Swagger `/docs`, схема `/openapi.json` и Postman доступны как раньше. UI не является обязательным слоем интеграции. Ключ вводится пользователем и передаётся только заголовком, без cookies/URL/storage. Подробности — [WEB.md](WEB.md).

## Помощник по замечанию v0.8

`POST /api/v1/reports/{report_id}/assistant` — JSON: finding_index, action=explain/fix/rephrase/question, use_llm=false, allow_external_transfer=false, необязательные question/selected_text по действию. Explain/fix доступны локально. Для модели нужны два разрешения и Idempotency-Key; переформулировка требует выбранного текста. Ответ AssistantResponse не меняет AnalysisResponse, имеет собственные method/provider/status, answer/steps/suggestion/sources/warnings. Ошибки — 404/409/410/413/422/502/503; сбой помощника не превращает исходный отчёт в partial. GET /capabilities дополнен finding_assistant. Остальной API совместим; единственное изменение схемы — аддитивная таблица Alembic 0003. [Полный контракт](ASSISTANT.md).
