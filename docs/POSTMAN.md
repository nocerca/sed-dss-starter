# Работа через Postman

Подготовлены файлы импорта Postman Collection v2.1:

- [Коллекция запросов](../postman/SED-DSS.postman_collection.json).
- [Окружение localhost](../postman/SED-DSS.local.postman_environment.json).
- [Синтетический DOCX](../examples/postman_synthetic.docx) для первых проверок.

В JSON нет ключей пользователя. Коллекция обращается к нашему API на `127.0.0.1:8000`; ключ Z.AI и внутренний токен OpenClaw остаются на стороне сервиса. Коллекция подготовлена как импортируемые файлы; интерфейс установленного Postman автоматически не изменялся.

## Импорт

1. Запустите Docker Desktop. Из корня проекта выполните `docker compose up -d --build`.
2. В Postman нажмите **Import → Files**, выберите оба JSON из папки `postman`.
3. В списке окружений выберите **SED-DSS — localhost**.
4. В окружении заполните `app_api_key`: значение **APP_API_KEY** из локального `.env`. Это ключ нашего приложения; **ZAI_API_KEY сюда не подходит**. Храните значение локально, не публикуйте и не экспортируйте заполненное окружение.
5. `base_url` оставьте `http://127.0.0.1:8000`. `external_consent=false`, `allow_delete=false` оставьте до намеренного выполнения соответствующих запросов.
6. В настройках Postman укажите рабочую папку равной корню проекта. Либо в каждом запросе анализа откройте **Body → form-data → file → Select Files** и выберите `examples/postman_synthetic.docx`. Остальные параметры и авторизация уже заданы. Заголовок Content-Type вручную не добавляйте: Postman сам сформирует multipart boundary.
7. Установите таймаут запросов не меньше **180000 мс** (или `0`, без ограничения): бесплатная модель иногда отвечает медленно. Для localhost из веб-интерфейса нужен Desktop Agent; проще использовать установленный Postman Desktop.

## Первое прохождение

В папке **01 — Состояние сервиса** по очереди выполните живость, готовность БД и возможности. Должны вернуться HTTP 200. Живость сама по себе не проверяет модель.

В папке **02 — Анализ без модели** выполните **Проверить DOCX локально**. Ожидается HTTP 200, `mode=rules_only`, `status=completed`. Отчёт содержит замечание о фразе «в кратчайшие сроки». Исходный файл не меняется.

После него выполните **Повторить тот же запрос без нового анализа**, выбрав тот же файл и оставив те же поля. Должны вернуться тот же `id` и заголовок `Idempotency-Replayed: true`. После изменения файла/полей с прежним ключом сервер вернёт 409. Повторный Send первого запроса создаёт новый ключ и новый анализ.

Запрос **LLM без согласия** должен вернуть 409. Это ожидаемая успешная проверка защиты: текст модели не передаётся.

## Десять документов с ошибками

В коллекции добавлена папка **06 — Проверки по инструкции: 10 документов**. Перед проверкой выполните из корня проекта:

```powershell
.\.venv\Scripts\python.exe scripts/create_letter_demos.py
```

Десять DOCX находятся в `examples/private/postman_cases/incorrect`; два допустимых контроля — в `controls`. Это полностью искусственные письма. Папка исключена из Git/Docker, генератор воспроизводит файлы после клонирования. Подробности каждой правки и ожидаемые коды — `manifest.json` и README рядом.

Повторно импортируйте **коллекцию**, сохранив заполненное локальное окружение. Укажите рабочую папку Postman — корень проекта, либо выберите соответствующий файл в Body вручную. Запросы уже содержат `policy_profile=office_instruction_letters`, `use_llm=false`, `allow_external_transfer=false`. Каждый Send создаёт новый ключ операции. В Test Results проверяются HTTP 200, completed/provider=none и ожидаемый код.

| Файл | Ошибка | Ожидаемый код |
|---|---|---|
| 01_left_margin.docx | Левое поле 20 мм | ORG_MARGINS |
| 02_body_font.docx | Arial в основном тексте | ORG_BODY_FONT |
| 03_body_size.docx | Основной текст 16 пт | ORG_BODY_FONT_SIZE |
| 04_body_indent.docx | Абзацный отступ 0 | ORG_BODY_FIRST_LINE |
| 05_body_spacing.docx | Интервал 8 пт «точно» | ORG_BODY_LINE_SPACING |
| 06_recipient_size.docx | Адресат 10 пт | ORG_RECIPIENT_FONT |
| 07_executor_phone.docx | Нет телефона исполнителя | ORG_EXECUTOR_CONTACT |
| 08_executor_size.docx | Исполнитель 10 пт | ORG_EXECUTOR_FONT |
| 09_date_format.docx | Дата со слешами | ORG_DATE_FORMAT |
| 10_signature_font.docx | Подпись Calibri | ORG_SIGNATURE_FONT |

В findings смотрите `expected` и `observed`. В `metrics.policy_checks.results` — pass/violation/insufficient_data и основания. Нераспознанный реквизит не объявляется отсутствующим. Геометрия подписи и полнота всех реквизитов не подтверждаются.

Для контрольных файлов выберите DOCX из `controls`, оставьте тот же профиль; для реализованных правил нарушений не ожидается. Не применяйте к контролю тест «ожидается ошибка» из дефектного запроса. Дата `24 декабря 2025 г.` должна быть допустимой.

Автоматическая проверка всех десяти дефектов и двух контролей через работающий API:

```powershell
.\.venv\Scripts\python.exe scripts/check_letter_demos.py
```

## Анализ моделью

1. Убедитесь, что в `.env` выбраны `MODEL_BACKEND=zai`, `LLM_PROVIDER=openclaw`, `ALLOW_EXTERNAL_LLM=true`, сохранён `ZAI_API_KEY`. После изменения настроек пересоздайте API и шлюз.
2. В запросе **03 → Проверить DOCX с моделью** выберите разрешённый DOCX. Начните с синтетического примера.
3. В окружении установите **external_consent=true**. Это согласие отправить текст выбранного письма и найденный контекст базы знаний внешней модели. Автоматического обезличивания нет.
4. Нажмите **Send**. Скрипт потребит согласие и сразу сбросит окружение в `external_consent=false`, даже если ответ не придёт из-за таймаута. Только текущий запрос получит разрешённое значение. Без включения запрос отправляется с запретом и возвращает понятный HTTP 409; внешняя модель не вызывается.
5. Успешный результат: **HTTP 200, `mode=hybrid`, `provider=openclaw`, `status=completed`**. Замечания модели имеют `method=llm`, `verified=false`; их проверяет человек.

HTTP 200 со `status=partial`, `mode=rules_fallback` означает, что правила выполнены, а модельная часть не завершилась. Причина находится в `warnings`. Ноль замечаний модели допустим и не означает полноту проверки. Повторный Send этого запроса создаёт новый анализ; не запускайте параллельно несколько одинаковых проверок без необходимости.

В обновлённой коллекции есть **Локальные орфография и грамматика**: `use_language_checks=true`, модель выключена. Нужны профиль Docker `language` и `LANGUAGE_TOOL_ENABLED=true`; без них вернётся partial с сохранёнными правилами. Локальный модуль не требует `external_consent`. В ответе ищите `method=language_tool` и `metrics.language_check`. Для совместного использования можно включить оба модуля; partial может относиться к любому из них.

Тип документа по умолчанию теперь `unspecified`, демонстрационный `external_document_id` отключён: заполняйте реальные метаданные самостоятельно. После обновления импортируйте заново **коллекцию** из папки `postman`; заполненное окружение повторно импортировать не нужно, чтобы не сбрасывать локальный ключ.

`{{llm_idempotency_key}}` — автоматически генерируемый перед Send идентификатор анализа, не API-ключ. Без согласия он тоже заполняется; пустой заголовок больше не является штатным поведением коллекции. При ручном создании запроса заголовок можно вообще убрать. Длительности этапов — `metrics.timings_ms`; неизвестный/неисполненный этап имеет null.

После первого ответа поля коллекции `report_id` и `request_id` заполняются автоматически. В папке **04** можно прочитать последний созданный отчёт, список отчётов и найти отчёт по запросу. Удаление выполняется только при намеренной установке `allow_delete=true`; перед ним проверьте `report_id`. Удалённый отчёт не восстанавливается повтором прежнего ключа. Папка **05** показывает правила, историю версий и метаданные базы знаний; загрузка реального корпуса не выполняется.

## Как читать замечания

| Поле | Значение |
|---|---|
| `message` | Какой возможный недостаток найден |
| `evidence` | Цитата из письма или структурное доказательство |
| `recommendation` | Что предлагается уточнить |
| `category` | Язык, содержание или оформление |
| `severity` | Предварительная критичность `info`, `warning`, `critical` |
| `method` | `rule` — условие правила; `llm` — вывод модели; `language_tool` — локальный языковой модуль |
| `verified` | Для правила подтверждено условие; для модели всегда false. Это не сертификация ГОСТ |
| `fragment_id`, `rule_version` | Структурный адрес и версия правила, когда доступны |

Модель проверяет первые 12 000 символов, локальные правила — распознанный документ. Проверка рекомендательная: полная грамотность, логика и соответствие нормативам не гарантируются.

Если удобнее без Postman, откройте [Swagger](http://127.0.0.1:8000/docs), нажмите **Authorize**, вставьте `APP_API_KEY`, откройте `POST /api/v1/analyze → Try it out`, выберите DOCX. Для локального режима оставьте оба флага false; для внешней модели нужны `use_llm=true` и `allow_external_transfer=true`.

Повторная генерация импортов без чтения `.env`: `python scripts/export_postman.py`. Существующий DOCX-пример не перезаписывается. Полный REST-контракт — [API.md](API.md).
