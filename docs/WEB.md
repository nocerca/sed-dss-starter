# Веб-интерфейс

В v0.7 интерфейс доступен по адресу **http://127.0.0.1:8000/**. Его обслуживает тот же FastAPI; дополнительного frontend-сервера, npm-сборки и внешних шрифтов/CDN нет. Настройки `.env`, БД и модельные ключи браузеру не выдаются.

## Первая проверка

1. При запущенном Docker Compose откройте корневую страницу и нажмите **Подключить**.
2. Введите значение `APP_API_KEY` из локального `.env`. Это не `ZAI_API_KEY` и не токен OpenClaw. Ключ остаётся только в памяти вкладки, после перезагрузки нужен повторный ввод.
3. Выберите или перетащите DOCX. Лимит показывает сервер, по умолчанию 5 МиБ.
4. Выберите **Базовые проверки** либо **Инструкция по делопроизводству**. Второй вариант явно передаёт `policy_profile=office_instruction_letters` и включает реализованную часть требований вместе с эвристиками. Организация автоматически не угадывается.
5. При необходимости включите LanguageTool или модель. Переключатели доступны только при соответствующей серверной настройке; это не проверка живости внешнего провайдера. Сбой запрошенного компонента отображается как неполная проверка.
6. Нажмите **Проверить письмо**. Для модели отдельно подтвердите передачу текста и найденного контекста. Согласие сбрасывается перед отправкой каждого запроса, включая неудачный; оно не сохраняется между файлами.

По умолчанию обе дополнительные проверки выключены. Никакого автоматического обезличивания или отправки оригинала внешней модели нет: шлюзу передаются подготовленные текстовые данные при двух разрешениях. Исходный DOCX не редактируется.

## Чтение отчёта

- **Замечания** — только принятые результаты, с фильтром по оформлению, языку и содержанию. Раскройте карточку, чтобы прочитать рекомендацию, источник, структурное положение и технические свойства.
- **Ограничения и предупреждения** — что не проверено, причины сбоев и недостатка данных. При `partial` раздел раскрыт сразу.
- **Все результаты проверок** — подробный журнал профиля с фильтром `pass/violation/insufficient_data`; он свёрнут по умолчанию. Это не список дополнительных ошибок.
- **О проверке** — применённые правила, число абзацев, исходные тайминги и время текущего ответа. Попадание в кэш помечено отдельно; метрики исходного анализа при этом не пересчитываются.
- **Скачать JSON** — полный ответ API для последующего разбора. Выгрузка содержит имя, метаданные и цитаты; храните её как данные проверенного письма.

Положение «блок 8» — адрес структуры DOCX, не физическая страница Word. Превью DOCX, OCR и рендеринга страниц нет. Нулевой счётчик и `completed` не подтверждают отсутствие ошибок или полное соответствие инструкции/ГОСТ.

## История и правила

**Отчёты** загружаются по 20, с переходом между страницами. Поиск фильтрует только текущий загруженный список. Открытие отчёта вызывает GET, без нового анализа. У предварительного `processing` есть кнопка обновления; фоновой очереди и автоматического перезапуска нет.

**Правила** показывают действующие версии, включённость, основания, условия и исключения. Можно искать по коду/описанию и выбирать группу. На этой странице правила не редактируются. Ссылка на источник — идентификатор основания, а не автоматически опубликованная частная инструкция.

Если ответ POST потерян, форма при неизменном файле и параметрах повторяет тот же ключ операции. Автоматических повторов нет. Перед новой операцией посмотрите историю; изменение формы создаёт новый запрос. Каждый успешный новый запуск получает новый ключ, а кэш независимо может вернуть прежний отчёт. Для нового расчёта отключите кэш в дополнительных параметрах.

## Интеграции и приватность

REST `/api/v1` и его авторизация остаются прежними. Страница — один из клиентов API, а не обязательный промежуточный слой. Swagger — `/docs`, машинный контракт — `/openapi.json`, Postman продолжает работать. Новых обязательных параметров/изменений схемы БД нет.

Используется один origin: не нужны CORS `*`, выдача ключа OpenClaw браузеру или публичные порты БД/шлюза. Ключ вводится вручную, запросы передают его заголовком; cookies для авторизации не используются. Не включайте URL-параметры с ключами. Содержимое отчётов вставляется как текст, без исполнения HTML/Markdown; CSP запрещает внешние ресурсы и inline-скрипты. Ответы API и страницы имеют `Cache-Control: no-store`. Service Worker отсутствует. В localStorage сохраняется только светлая/тёмная тема.

Отключение очищает ключ и открытые отчёты из состояния интерфейса, но не удаляет записи сервера и не обещает очистку памяти браузера/ОС. История доступна всем обладателям общего ключа приложения; SSO и разграничение пользователей не реализованы. При развёртывании вне localhost нужен отдельный этап TLS/авторизации.

Вопросы помощнику, экспертная обратная связь, сравнение исправлений и свободный поиск по инструкции **ещё не реализованы**. Следующий этап — T24; интерфейс не показывает неработающие кнопки этих функций.

## Проверка интерфейса

```powershell
.\.venv\Scripts\python.exe -m pip install -e ".[dev,browser]"
.\.venv\Scripts\python.exe -m playwright install chromium
.\.venv\Scripts\python.exe tests/browser/check_frontend.py
node --test tests/frontend.test.mjs tests/openclaw-config.test.mjs tests/postman-scripts.test.mjs
```

Браузерный сценарий создаёт отдельную временную SQLite и локальный API. Реальный DOCX синтетический; модельные ответы имитируются, внешний провайдер отключён. Проверяются вход, формат файла, полный путь анализа/истории/выгрузки, фильтры, мобильный экран, тема, XSS, согласие, partial, повтор после потери ответа и отсутствие секретов в browser storage. Скриншоты можно сохранить в игнорируемый каталог: `--screenshots .research/frontend`. В CI Chromium устанавливается с `--with-deps`.
