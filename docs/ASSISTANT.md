# Помощник по замечанию — v0.8 / T24

Помощник объясняет одно замечание сохранённого отчёта. Он не видит весь DOCX, не изменяет исходник, не отправляет письма и не является свободным поиском по инструкции.

## В интерфейсе

1. Проверьте письмо или откройте готовый отчёт в истории.
2. Раскройте карточку и нажмите **Разобрать замечание**. Первое объяснение формируется локально, без передачи модели.
3. Выберите действие:

| Действие | Что получает автор |
|---|---|
| Объяснить замечание | Причину срабатывания и сохранённое основание правила |
| Как исправить | Рекомендацию и применимые шаги в Word; значения сверяются с самим замечанием |
| Предложить формулировку | Вариант выбранного пользователем текста, только через модель |
| Задать вопрос | Самостоятельный вопрос в контексте выбранного замечания, только через модель |

Объяснение и шаги работают без модели. Их можно дополнительно уточнить переключателем **Уточнить с моделью**. Для внешнего запроса каждый раз подтвердите передачу. Согласие сбрасывается до отправки, в том числе при ошибке; ввод нового текста также снимает флажок.

Для переформулировки самостоятельно вставьте от 3 до 2000 символов. Для вопроса — от 3 до 1000, дополнительный фрагмент необязателен. Полный текст письма не восстанавливается из отчёта. Поля, скрытые для действия, не отправляются. Каждый вопрос самостоятельный: предыдущие ответы не используются как история диалога.

Готовый вариант можно скопировать кнопкой; DOCX остаётся прежним. Проверьте смысл, имена, организации и факты. Если модель сообщает о недостатке данных, уточните вопрос или добавьте разрешённый фрагмент.

## REST для интеграций

`POST /api/v1/reports/{report_id}/assistant`, `Content-Type: application/json`, `X-API-Key`.

Минимальный локальный запрос:

```json
{"finding_index": 0, "action": "explain"}
```

Вопрос модели:

```json
{
  "finding_index": 0,
  "action": "question",
  "question": "Почему эта формулировка неоднозначна?",
  "use_llm": true,
  "allow_external_transfer": true
}
```

Для модели **обязателен Idempotency-Key**, например UUID; локально он необязателен. JSON-флаги — boolean, строки `"true"` не принимаются. Finding_index — индекс с нуля в исходном `findings`, а не в отфильтрованном списке. `question` допустим только для question, `selected_text` — для question/rephrase. Неизвестные поля и история диалога отклоняются. Все поля/ответы описаны в Swagger и OpenAPI.

В Postman добавлена папка **08 — Помощник по замечанию**. Сначала создайте отчёт с замечаниями; `report_id` заполняется запросом анализа. При необходимости поменяйте индекс 0. Для двух модельных запросов перед каждым Send задайте `external_consent=true`: скрипт превращает его в JSON boolean и расходует до отправки. Не переимпортируйте своё окружение поверх заполненных локальных значений.

## Контекст и основания

Для локального ответа берутся сохранённые свойства замечания и **точная историческая версия** `RuleVersion`, указанная в нём. Изменение текущей конфигурации не подменяет основания старого отчёта. Если версия/ссылка не совпала либо отсутствует, помощник не придумывает норму и сообщает об ограничении. У LanguageTool и LLM может не быть локальной спецификации.

Для вопроса/объяснения/порядка исправления модель получает действие, выбранное замечание, формализованное основание/исключения (если найдены), вопрос и вставленный фрагмент. Для rephrase — отдельное редакторское задание, selected_text и только код/категория замечания: новый фрагмент мог уже исправить старую ошибку, его не нужно повторно оценивать по прежней цитате. Нормативное основание для rephrase не передаётся, sources пуст. Общий контекст ограничен 16 000 символов JSON. Имя файла, UUID отчёта/исходного запроса и внешний ID СЭД как метаданные не передаются. Это не автоматическое обезличивание: сведения внутри цитаты, вопроса или вставленного текста могут попасть модели при согласии. База знаний, другие замечания, история диалога и исходный файл не добавляются.

Все LLM-запросы идут через существующий изолированный OpenClaw, с новой непрозрачной сессией, без инструментов/команд/доступа к файлам и без обхода на прямой API провайдера. Глобальное разрешение и согласие проверяются **до** идемпотентного повтора. Сетевые ограничения/обработка ошибок общие с анализом письма.

Ответ модели проверяется по ограниченной JSON-схеме. `source_refs` допускаются только из переданных оснований. Предложение разрешено только для rephrase; при insufficient_data его быть не может. Для готового предложения сравниваются наборы цифровых токенов, email и URL: явная подмена/добавление отбрасывается. Точка в конце предложения не считается изменением даты. В rephrase подпись «без изменений»/«предложен вариант» формирует приложение сравнением строк, не доверяя описанию правки самой моделью. Это консервативная техническая проверка, не доказательство сохранения смысла, имён или всех фактов. Свободный текст ответа полностью не верифицируется. Формализованное требование не выдаётся за дословную цитату оригинала инструкции; источник инструкции пока не подтверждён экспертом.

`AssistantResponse` содержит `method=local|llm`, `provider=none|openclaw`, `status=completed|insufficient_data`, объяснение `answer`, шаги `steps`, необязательный `suggestion`, существующие спецификации `sources` и ограничения `warnings`. Completed означает сформированный ответ, не подтверждённую истинность. В оригинальном отчёте mode/status/findings не меняются.

## Повтор, ошибки и хранение

- Неизменный запрос с тем же ключом возвращает сохранённый ответ с `Idempotency-Replayed=true` без нового модельного вызова. Исходный request_id в теле сохраняется, текущий — в HTTP-заголовке. Изменение вопроса/действия/параметров с прежним ключом даёт 409.
- Если операция уже processing, ответ — 409/Retry-After=2. После прерывания сервера маркер может остаться; автоматического повторного вызова нет. Не создавайте новый ключ для неизвестного исхода без понимания возможного повторного внешнего вызова.
- Если ответ сети потерян, интерфейс сохраняет прежний ключ для неизменной формы. Для повтора модели нужно новое согласие. Автоматических POST-повторов нет.
- Предусмотренный сбой модели/валидации — отдельный HTTP 502, без технического тела провайдера; исходный отчёт остаётся доступен. Маркер failed предотвращает новый вызов по тому же ключу. Для отдельной ручной попытки есть **Новая попытка**, новое согласие и новый ключ. Неопределённый исход у внешнего провайдера не превращается в гарантию однократного исполнения.
- Ошибка БД — безопасный 503; повторяйте с прежним ключом. Несуществующие отчёт/индекс — 404, некорректное тело — 422, большой контекст — 413.

Alembic **0003** добавляет `assistant_operations`: HMAC ключа/параметров, ссылку на отчёт, статус, время и ограниченный ответ. Исходные ключ, вопрос и selected_text отдельно не сохраняются, но модель может процитировать их в сохранённом ответе. Без ключа локальный ответ не сохраняется. Ответы считаются данными письма и доступны обладателю общего APP_API_KEY, без разграничения пользователей.

Удаление исходного отчёта через API или retention удаляет содержимое связанных ответов и связь с отчётом. Обезличенные маркеры ключей остаются: повтор с прежним ключом даёт 410 и не вызывает модель. Browser storage содержит только тему; вопрос/фрагмент/ответ живут в состоянии вкладки, отключение их очищает. Политика временных сессий/хранения у внешнего провайдера прежняя; немедленное удаление после ответа не гарантируется. Кэш тяжёлых отчётов к помощнику не применяется, а идемпотентность операции — применяется.

## Проверка и границы

Автотесты используют только синтетические материалы: локальные ответы, историческую версию, недоступные основания, строгие поля, двойное согласие даже для повтора, отсутствие метаданных в payload, отдельные сессии, ложные ссылки/числа, сбои, конкуренцию, удаление/retention и удаление отчёта во время ожидания. Chromium проверяет индекс после фильтрации, локальную помощь, вопрос/формулировку, недостаток данных, XSS как текст, согласие и повтор после потери ответа. Изолированный настоящий OpenClaw с тестовой моделью проверяет весь REST/БД/шлюз-маршрут без выхода в интернет.

Экспертная точность и польза на реальных письмах не измерены. Нет свободного поиска по всей инструкции, семантического RAG, произвольных агентных инструментов, автоматической правки DOCX или отправки писем. Обратная связь эксперта и сравнение исправленных версий — отдельные этапы.
