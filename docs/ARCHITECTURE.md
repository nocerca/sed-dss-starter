# Устройство проекта

Наше приложение получает письмо, выполняет проверки и собирает отчёт. PostgreSQL хранит отчёты, версии правил и материалы базы знаний. OpenClaw организует разрешённое обращение к выбранной модели; текст анализирует модель.

В v0.7 `/` обслуживает небольшой веб-клиент на HTML/CSS/ES modules. Он обращается к тем же `/api/v1` на том же origin; интеграции могут использовать REST напрямую. Ассеты поставляются с Python-пакетом и Docker API, отдельной сборки/Node runtime нет. `app/frontend.py` ограничивает статику каталогом `app/static`, задаёт корректный MIME модулей, корневая страница исключена из OpenAPI. Middleware добавляет CSP/no-store/referrer/nosniff для интерфейса, не меняя Swagger. Приватные данные рендерятся текстовыми узлами; ключ/отчёты не записываются в browser storage, сохраняется только тема. [Контракт интерфейса](WEB.md).

`config/letter_policy.json` и `docs/LETTER_POLICY.md` описывают профиль по предоставленной инструкции. Реализованные 16 проверок/диагностик включены в активный `config/rules.json` с основаниями, условиями и явным фильтром `policy_profile`. `app/letter_checks.py` выделяет роли блоков, проверяет доступные свойства и возвращает pass/violation/insufficient_data. Геометрия страницы и полный состав реквизитов не выводятся из текста. `scripts/export_letter_policy.py` валидирует каталог и формирует документацию; локальные привязка источника/инвентаризация остаются в игнорируемой папке.

```text
Веб-интерфейс / СЭД / Swagger / Postman
              |
           FastAPI
              +--> разбор DOCX --> применимые правила ------+
              |                                            |
              +--> согласие --> поиск контекста             |
```

## Данные и ограничения

Полный текст анализируемого письма не записывается в БД; в отчёте есть имя файла, метаданные и короткие цитаты. Тексты базы знаний сохраняются. Ключ идемпотентности и содержимое запроса хранятся только как HMAC; секрет HMAC нельзя менять без понимания, что прежние ключи перестанут распознаваться.

Кэш живёт в одном процессе API и содержит только случайно ключеванный HMAC, ID и монотонный срок действия. Повторный запрос читает существующий отчёт из БД; исходники/выводы модели в памяти кэша не дублируются, срок хранения отчёта не продлевается. @lru_cache не оборачивает async-анализ: [документация Python](https://docs.python.org/3/library/functools.html#functools.lru_cache) отмечает удержание аргументов и возможность параллельного повторного вычисления. Наш кэш хранит только метаданные и явно резервирует активный ключ. Подробности — [CACHE.md](CACHE.md).

До вызова модели отчёт правил уже записан. Если процесс прервётся, он останется `processing`: повтор с прежним ключом даст 409, автоматической повторной передачи не будет. При предусмотренной ошибке шлюза сохраняется `partial`.

Удаление отчёта оставляет обезличенный маркер использованного ключа: повтор с ним возвращает 410. Это не вызывает модель повторно. Автоматического удаления корпуса нет.

DOCX-разбор не открывает ссылки, не выполняет коды полей и не пересчитывает их кэш. Физические страницы, координаты, темы Word, изображения, текстовые поля и правки не интерпретируются полностью. Адрес `fragment_id` структурный, не визуальный.

Необязательный LanguageTool — отдельный сервис во внутренней сети `language`, без опубликованного порта, интернета и ключей моделей. Он использует фиксированный дистрибутив 6.6, а не публичный API. Основной API подключён к этой сети и к сети остальных компонентов. Включение локальных проверок не даёт разрешения на внешнюю передачу.

Замеры `metrics.timings_ms` измеряют фактические этапы. `llm_gateway_ms` включает весь вызов OpenClaw и обработку результата: время внутри шлюза и у внешнего провайдера отдельно не установлено. `total_before_final_save_ms` не включает финальную запись/сериализацию. `Server-Timing` относится к текущему HTTP-запросу, включая быстрый идемпотентный повтор.

Дерево оставлено плоским: REST и сборка результата в `main.py`, самостоятельные механизмы — в отдельных модулях. Дублирующая стартовая инструкция, старый генератор/текстовые образцы и неиспользуемая обёртка правил удалены. Пользовательские DOCX в `examples/` игнорируются Git/Docker. В Docker зависимости устанавливаются отдельным кэшируемым слоем; правки исходников не требуют повторного скачивания всех зависимостей.
