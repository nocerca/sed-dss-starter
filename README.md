# SED-DSS — проверка исходящих деловых писем

Исследовательский прототип v0.5: принимает DOCX и возвращает объяснимые замечания. Автор сам решает, что исправлять. Сервис не отправляет письма и не изменяет оригиналы. Проверка полного соответствия ГОСТ и доказанная экспертная точность не заявляются.

Без модели доступны пять демонстрационных эвристик: отсутствие распознанного текста, расплывчатый срок, неопределённый предмет запроса, длинный абзац и несколько явно заданных шрифтов. [Применимость правил](docs/RULES.md).

Дополнительно подключён **локальный LanguageTool 6.6** для начальной русской орфографии/грамматики без внешней модели. Он включается отдельно: профиль Docker `language`, `LANGUAGE_TOOL_ENABLED=true`, поле запроса `use_language_checks=true`. [Настройка](docs/SETUP.md).

Профиль `policy_profile=office_instruction_letters` включает **16 локальных проверок и диагностик по предоставленной инструкции**: поля, шрифты/размеры реквизитов, абзацный отступ, часть интервалов, даты, контакт исполнителя и подпись. Это реализованная часть [полного каталога требований](docs/LETTER_POLICY.md). Роли блоков определяются консервативно; недостаток данных отражается в `metrics.policy_checks`, без выдуманного нарушения. Профиль организации выбирается явно. Полученные 41 письмо требуют экспертной разметки.

Для ручной проверки есть [десять документов с контролируемыми ошибками и готовые запросы Postman](docs/POSTMAN.md#десять-документов-с-ошибками). Создать синтетические файлы: `python scripts/create_letter_demos.py`. Проверить их через API: `python scripts/check_letter_demos.py`. Реальные письма и инструкция не включаются в Git или Docker.

В отчёте появились локальные признаки жанра, счётчики изображений/заголовков, причины отклонения модельных выводов и замеры этапов. Содержимое скриншотов не распознаётся. Консервативный фильтр уменьшает известные классы необоснованных замечаний; его точность на реальных письмах пока не измерена.

## Запуск

Из корня проекта при работающем Docker Desktop:

```powershell
python scripts/setup_local.py
docker compose config --quiet
docker compose up -d --build
python scripts/smoke_test.py
```

Настройки по умолчанию — `LLM_PROVIDER=none`, `ALLOW_EXTERNAL_LLM=false`. GPU и ключ модели не нужны. `.env` не перезаписывается шаблоном, недостающие внутренние секреты генерируются без вывода.

- [Swagger UI](http://127.0.0.1:8000/docs): кнопка Authorize, значение `APP_API_KEY` из `.env`.
- [Живость](http://127.0.0.1:8000/health/live), [готовность БД](http://127.0.0.1:8000/health/ready).
- Остановка: `docker compose down`, без удаления тома БД.

## Подключение модели

Маршрут всегда проходит через изолированный OpenClaw. Выбор: `MODEL_BACKEND=yandex|gigachat|zai`.

**Подключён и проверен Z.AI / GLM-4.7-Flash:** [настройка](docs/SETUP_ZAI.md). Реальная генерация на синтетическом письме через OpenClaw подтверждена 25.10.2026. Варианты Яндекса и GigaChat сохраняются: [общая настройка](docs/SETUP.md); их реальная генерация отдельно не проверялась.

Для работы подготовлены [коллекция Postman и инструкция](docs/POSTMAN.md); можно использовать также Swagger.

Письма и фрагменты базы знаний могут передаваться модели только при глобальном разрешении и согласии конкретного запроса. История шлюза находится в памяти контейнера; немедленное удаление после ответа не гарантируется. Пока используйте синтетические или разрешённые обезличенные материалы.
